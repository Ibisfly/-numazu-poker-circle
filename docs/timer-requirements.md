# アプリ内トーナメントタイマー 要件メモ

- ステータス: **保留（未実装）**
- 作成日: 2026-07-10
- 背景: 現在は外部タイマーアプリ（timer-black-swan.web.app）に `timerSessionId` で紐付け、精算時に `getTimerProvisionalRankings` で暫定順位を取り込んでいる。これをアプリ内蔵に置き換える構想。

## 1. ストラクチャー（ブラインド構成）管理

- レベルごとの SB / BB / アンティ / 時間（分）を定義できる
- 休憩レベルを挿入できる
- プリセットとして保存・再利用できる（毎回入力は運用に耐えない）
  - Firestore `structures` コレクションを想定

## 2. タイマー本体（管理者操作）

- 開始 / 一時停止 / 再開 / レベルスキップ / 1つ戻す / 残り時間の±調整
- 表示項目:
  - 現在レベル・SB/BB/アンティ・残り時間
  - 次レベルの予告
  - 残り人数 / 総エントリー数
  - 平均スタック
  - プライズ（順位別褒章）
- レベルアップ時の通知: 音・バイブ・画面点滅

## 3. マッチ連携（内蔵化の最大のメリット）

- マッチの参加者・リエントリー / リバイ数から総チップ・平均スタックを自動計算
- 脱落（ノックアウト）を管理者がタップで記録
  - 脱落順から暫定順位を自動生成
  - 既存のトーナメント精算モーダルに自動入力（外部API連携が不要になる）

## 4. 同期・マルチ端末

- Firestore `onSnapshot` でリアルタイム同期（既存アーキテクチャ踏襲）
- 3つの閲覧形態:
  1. 管理者の操作画面
  2. 会場モニタ用の全画面表示モード（横向き・大型表示）
  3. メンバーのマッチ詳細への簡易表示（現在レベル・残り時間）
- 権限は firestore.rules で制御: 操作 = admin、閲覧 = active メンバー

## 5. 技術要件（設計の肝）

- **残り時間を秒単位で Firestore に書かない**（書き込みコストが爆発する）
  - 「レベル終了時刻の Timestamp」を保持し、各クライアントがローカルでカウントダウン計算
  - 一時停止中は残余ミリ秒を保持
  - 書き込みは状態変化時のみ（開始 / 停止 / レベル変更 / 脱落）
- 端末の時計ズレ補正（serverTimestamp との差分オフセット）
- 画面スリープ防止（Screen Wake Lock API。iOS Safari は制約あり）
- 音の自動再生制約への対応（ユーザー操作後に AudioContext を初期化）
- オフライン耐性: 一時切断中もローカル進行し、再接続で補正

## 6. データモデル案

```
timerSessions/{id}
├── matchId: string
├── structureId: string
├── levels: [{ sb, bb, ante, minutes, isBreak }]
├── state: 'idle' | 'running' | 'paused' | 'finished'
├── levelIndex: number
├── levelEndsAt: Timestamp      // running時のみ有効
├── pausedRemainingMs: number   // paused時のみ有効
└── eliminations: [{ uid, rank, at }]
```

- 複数管理者の同時操作は「最後の書き込み勝ち」で許容（規模的にトランザクション必須ではない）
